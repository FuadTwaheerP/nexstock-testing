# Bug-reporting format

For future detailed bug lists in this project, use Markdown and give each bug its own heading/ID followed by these sections in this exact order:

1. Title
2. Environment
3. Priority
4. Step-by-step
5. Expected Result
6. Actual Result
7. Attachment
8. Comment

Use numbered reproduction steps. Add a Markdown horizontal rule (`---`) on its own line after every bug, including the last bug, with blank lines before and after it.

Keep confirmed application bugs separate from corrected automation issues and unconfirmed requirement/policy observations. Group duplicate failures caused by the same missing capability into one ticket. Do not present unverified behaviour as a confirmed bug.
