# Dashboard & Executive Analytics - Phase 2 findings

Test date: **2026-10-25**. Production: https://nexstock.stylotech.mu/app. Company: **Nexstock QA Company**. Chromium/Windows.

## Execution summary

Final composite results: **4 passed, 7 application-failing cases, 0 blocked, 0 unresolved automation issues**. Duplicate failures are grouped into **4 confirmed tickets**. Setup/cleanup are included in the count, not feature coverage. Later focused reruns replace the same earlier cases.

A green assertion verifies only its exercised scenario. A failed full flow does not certify the steps it could not reach; independent steps attempted after a failure are recorded in its attachment. Missing/deferred prerequisites are not bugs or passing coverage. No intentionally skipped or expected-failure cases are used.

## Coverage limits / prerequisites

- Low-stock arithmetic checks existing QA rows against displayed thresholds; this is not a new-alert delivery/timing test.
- Recent Activity checks existing sales and stock entries, not a seeded fresh event or every stream ordering boundary.
- Configured widgets are saved only in isolated test-browser layout state, not the user's desktop browser. No company setting or transaction is written. Failed source binding blocks meaningful widget financial/date certification.
- AOV/revenue source values are a binding oracle; underlying transaction eligibility/rounding/date boundaries require further reconciliation after live widgets are fixed.

## P2-DASH-003

### Title

Saved configured Dashboard widgets render sample values or the wrong selected data source

### Environment

Production NexStock; Nexstock QA Company; Chromium 1920 x 1080; Windows; 2026-10-25. Requirements: F01-a, F01-b, F01-c.

### Priority

High

### Step-by-step

1. Open Dashboard in Nexstock QA Company and let the live reporting data load.
2. Choose Customize Dashboard, Add Widget, then Stat Card. Give it a QA title and select Revenue; add it and Save Layout in the isolated QA browser.
3. Compare the rendered Revenue with the reporting/dashboard/stats response generated by that same screen.
4. Repeat with Total Orders and Avg. Order Value.
5. Add and save a Line Chart using Revenue Trend and inspect its displayed month labels against the live revenue series.
6. Add and save a Data Table using Top Products; inspect the rendered columns and products.
7. Remove only the test widgets in the isolated browser to return to the original default layout.

### Expected Result

Each saved widget uses its selected data source and the current QA company's live values. Top Products shows sales quantity/revenue ranking, not an unrelated low-stock table.

### Actual Result

The observed live response has revenue 5,890, 34 orders and AOV 173.24, while configured Stat Cards show Rs 458,920.00, 1,156 orders and Rs 397.00. Top Products renders a low-stock table with Current/Min/Store/Status columns and sample items such as Laptop Charger/HDMI Cable. The configured line chart also renders sample month labels instead of the live May-October revenue series.

Affected cases:

- Dashboard complete analytics flow
- F01-a revenue orders and AOV widgets bind hydrated values and reconcile the ratio
- F01-c top products exposes quantity and revenue performance
- F01-b saved revenue trend renders the selected sales data source
